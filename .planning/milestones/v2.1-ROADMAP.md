# Archive: v2.1 Advanced SVG Conversion

**Status:** Shipped
**Phases:** 26–28 (3 phases)
**Shipped:** 2026-05-08

---

## Goal

实现 SVG 高级视觉元素到 DrawingML 的转换，使 SVG 管线支持渐变填充、裁剪路径和图案填充

---

## Phases

### Phase 26: Gradient Fill (linear + radial → DrawingML)

**Status:** Shipped | **Tests:** 22

- SVG `<linearGradient>` / `<radialGradient>` → DrawingML `gradFill`
- Gradient stops: offset, stop-color, stop-opacity correctly mapped
- `url(#gradientId)` references resolved in fill/stroke
- SVG QA: gradient tags not banned
- Two parallel modules: `converters.py` (direct XML) and `gradient_fills.py` (python-pptx API)

### Phase 27: Clip-Path & Mask (customGeometry clip)

**Status:** Shipped | **Tests:** 19

- SVG `<clipPath>` → DrawingML `a:clipPath` with custom geometry
- SVG `<mask>` → binary clip (no alpha, OOXML limitation)
- `clip-path`/`mask` attributes resolved and applied via exporter
- 6 child element types: path, polygon, polyline, rect, circle, ellipse

### Phase 28: Pattern Fill (blipFill tile)

**Status:** Shipped | **Tests:** 15

- SVG `<pattern>` → DrawingML `a:blipFill` with `a:tile` tiling
- Pattern children rendered to PNG via Pillow (rect, circle, line)
- Image relationship added to slide part
- Graceful degradation without Pillow

## Known Limitations

- Mask alpha/semi-transparency not supported (OOXML constraint)
- Only first child of clipPath/mask processed
- Pattern children limited to rect/circle/line
- `clipPathUnits`/`patternUnits` not implemented
