# Requirements: Slide Skill

**Defined:** 2026-05-01
**Last revised:** 2026-05-01 after PPT Master research
**Core Value:** Agents can produce and modify PowerPoint decks that are valid, visually reviewable, natively editable, and backed by repeatable QA evidence.

## v1 Requirements

### Foundation

- [x] **FND-01**: Maintainer can see a documented boundary that forbids copying proprietary Anthropic skill text or code.
- [x] **FND-02**: Maintainer can see MIT attribution rules for any deliberate reuse from `hugohe3/ppt-master`.
- [x] **FND-03**: Maintainer can see the local repository structure for skill docs, toolkit code, examples, tests, and planning artifacts.
- [x] **FND-04**: Agent can load a concise local skill entrypoint that routes deck tasks to intake, SVG generation, export, editing, or QA workflows.
- [x] **FND-05**: Maintainer can run a baseline verification command that confirms repository health for the current phase.

### Source Intake

- [x] **SRC-01**: Agent can normalize Markdown or pasted text into a deck project source file.
- [x] **SRC-02**: Agent can convert PDF source material to Markdown with preserved reading order where feasible.
- [x] **SRC-03**: Agent can convert DOCX/HTML-like document source material to Markdown.
- [x] **SRC-04**: Agent can convert spreadsheet source material to Markdown while preserving sheet/table structure.
- [x] **SRC-05**: Agent can extract existing PPTX content to Markdown for read/analyze workflows.
- [x] **SRC-06**: Agent can initialize a per-deck workspace with `sources`, `images`, `svg_output`, `svg_final`, `notes`, `exports`, and `backup` conventions.

### SVG Design Pipeline

- [x] **SVG-01**: Agent can create a human-readable design specification before generating slides.
- [x] **SVG-02**: Agent can create a machine-readable spec lock for canvas, palette, typography, icon set, images, and page rhythm.
- [x] **SVG-03**: Agent can generate SVG slide pages with fixed canvas dimensions and valid XML.
- [x] **SVG-04**: Agent can use semantic top-level SVG groups with stable IDs for editability and optional animation anchors.
- [x] **SVG-05**: Toolkit can reject banned or unsupported SVG features before export.
- [x] **SVG-06**: Toolkit can finalize SVG pages for export-safe images, icons, text runs, and compatible geometry.

### Native Export

- [x] **EXP-01**: Toolkit can convert finalized SVG pages into a `.pptx` deck.
- [x] **EXP-02**: Exported PPTX uses native editable PowerPoint objects where supported, not one full-slide raster image per page.
- [x] **EXP-03**: Toolkit can embed or preserve speaker notes generated from `notes/total.md`.
- [x] **EXP-04**: Toolkit can create backup artifacts: SVG snapshot deck and archived SVG source files.
- [x] **EXP-05**: Toolkit can validate exported PPTX package integrity and report export failures clearly.

### Editing

- [x] **EDT-01**: Agent can analyze an existing template deck and map desired content to suitable slide layouts.
- [x] **EDT-02**: Toolkit can import or inspect a PPTX template without mutating the original file.
- [x] **EDT-03**: Toolkit can duplicate, delete, and reorder slides without corrupting relationships.
- [x] **EDT-04**: Agent can replace placeholder text/content while preserving formatting where appropriate.
- [x] **EDT-05**: Toolkit can clean orphaned slides, media, and relationships after structural edits.

### QA

- [x] **QA-01**: Agent can run source/content QA to detect missing content, wrong order, and placeholder leftovers.
- [x] **QA-02**: Agent can run SVG QA before export and block on hard errors.
- [x] **QA-03**: Agent can render exported PPTX to per-slide images for visual inspection.
- [x] **QA-04**: Agent can run visual QA against rendered slide images using a documented issue taxonomy.
- [x] **QA-05**: Agent must complete at least one fix-and-verify cycle before declaring a generated or edited deck complete.
- [x] **QA-06**: Maintainer can inspect stored QA artifacts for completed examples or test runs.

### Documentation And Release

- [x] **DOC-01**: User can read clear setup instructions for required local dependencies and optional enhancements.
- [x] **DOC-02**: User can follow recipes for intake, SVG generation, export, editing, and verifying decks.
- [x] **DOC-03**: Maintainer can run regression tests for scripts and examples.
- [x] **DOC-04**: User can install or copy the local skill package into a Codex-compatible skills directory when ready.

## v2 Requirements

### Advanced Output

- **ADV-01**: Toolkit can add native PowerPoint transitions and per-group entrance animations.
- **ADV-02**: Toolkit can generate audio narration from notes and embed recorded narration in the PPTX.
- **ADV-03**: Toolkit can export or validate vertical/social/banner canvas formats beyond PPT 16:9.
- **ADV-04**: Toolkit can calibrate chart coordinates against source data before export.

### Compatibility

- **CMP-01**: Maintainer can compare render output across LibreOffice and Microsoft PowerPoint.
- **CMP-02**: Agent can generate accessibility checks for alt text, reading order, and contrast.
- **CMP-03**: Toolkit can support PPTX comments and richer speaker notes editing.

### Design Intelligence

- **DSN-01**: Agent can select from a richer local library of layout archetypes based on content type.
- **DSN-02**: Agent can produce before/after visual diffs for edited decks.

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Copying upstream Anthropic skill files | Proprietary license restrictions and clean-room goal. |
| Blindly vendoring PPT Master source | MIT allows reuse with attribution, but this project should first define local needs and preserve license obligations. |
| Full GUI presentation editor | Not needed for an agent skill/toolkit MVP. |
| Cloud service deployment | Local deterministic workflows come first. |
| Pixel-only PPTX export | Violates the native editability core value. |
| Pixel-perfect compatibility claims across every office suite | Requires later compatibility matrix and evidence. |
