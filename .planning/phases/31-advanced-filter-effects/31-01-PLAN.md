## Implementation Steps

### Wave 1: Core filter detection and emission (filter_effects.py)

All steps in this wave modify the same file in a tightly coupled chain. Execute sequentially.

#### Step 1 — Extend `_parse_filter()` to detect soft edge and glow

Extend the existing `_parse_filter()` function (line 27) to detect two new filter patterns alongside existing blur and shadow detection. The function currently returns `{"blur": ..., "shadow": ...}` — extend to `{"blur": ..., "shadow": ..., "glow": ..., "soft_edge": ...}`.

**Detection logic (from CONTEXT.md D-01 through D-16):**

1. Add `feComposite` and `feMerge` collection alongside existing `feGaussianBlur`, `feOffset`, `feFlood` iteration.
2. Track `feComposite` attributes: `operator`, `in`, `in2`.
3. After iterating all children, apply **detection priority order** (D-04, D-08):
   - **Shadow** (existing): If `feOffset` or `feDropShadow` present with non-zero dx/dy
   - **Glow** (new): If `feFlood` present AND `feComposite` with `operator="in"` present AND no `feOffset` (or zero offset)
   - **Soft edge** (new): If `feGaussianBlur` with `in="SourceAlpha"` AND no `feFlood` AND no `feOffset`
   - **Blur** (existing): Fallback for unrecognized patterns with blur data
4. Glow takes precedence over soft edge when both blur(SourceAlpha) and feFlood+feComposite are present (D-02).
5. `in="SourceAlpha"` required for glow and soft edge (D-05). `SourceGraphic` or no `in` stays as blur.
6. `feComposite operator="in"` required specifically for glow (D-06).
7. Glow color comes from `feFlood` `flood-color` and `flood-opacity` (D-07, D-14).
8. Default glow color: black (#000000), 100% opacity (D-14).
9. A single blur used by both offset→shadow AND flood+composite→glow produces both effects (D-13).

**Return dict structure:**
```python
{
    "blur": {"stdDeviation": float} | None,
    "shadow": {...} | None,
    "glow": {"stdDeviation": float, "flood_color": str, "flood_opacity": float} | None,
    "soft_edge": {"stdDeviation": float} | None,
}
```

**Key constraint:** If `soft_edge` is detected, do NOT also populate `blur` — they are mutually exclusive per D-23. But `glow` and `shadow` CAN coexist per D-24.

#### Step 2 — Extend `apply_filter_to_shape()` to emit glow and softEdge XML

Modify the existing `apply_filter_to_shape()` function (line 106) to handle the two new effect types. The function currently checks for `blur` and `shadow` — extend to also check for `glow` and `soft_edge`.

**Implementation:**

1. Add early return if ALL four effect keys are `None` (D-20).
2. Build all effect children in the `effectLst` in a single pass — do NOT remove/recreate for each type (D-25, avoids Pitfall 16):
   - **blur**: existing `<a:blur rad="N"/>` — BUT skip if `soft_edge` is also present (D-23)
   - **soft_edge**: `<a:softEdge rad="N"/>` where `rad = max(int(stdDeviation * 25400), 1)` (D-22, D-29, D-30)
   - **glow**: `<a:glow rad="N"><a:srgbClr val="COLOR"><a:alpha val="PCT"/></a:srgbClr></a:glow>` (D-21)
     - `rad = max(int(stdDeviation * 25400), 1)` (D-28, D-30)
     - Color from `glow["flood_color"]`, alpha from `int(glow["flood_opacity"] * 100000)` (D-31, D-32)
   - **shadow**: existing `<a:outerShdw>` logic — unchanged
3. Skip individual effects with invalid data (e.g., negative stdDeviation clamped to 0) without aborting others (D-26, D-34).
4. After building all children, call `_reorder_effect_lst()` to enforce XSD ordering.
5. Keep existing `_reorder_sppr()` call to position `effectLst` within `spPr`.

#### Step 3 — Add `_reorder_effect_lst()` function

New function in `filter_effects.py` that sorts children within `<a:effectLst>` to match the OOXML XSD sequence for `CT_EffectList`:

```python
EFFECT_ORDER = ["blur", "fillOverlay", "glow", "innerShdw", "outerShdw", "prstShdw", "reflection", "softEdge"]
```

Subset used in this codebase: `blur`, `glow`, `outerShdw`, `softEdge` (D-18).

**Implementation:**
- After all effect children are added to `effectLst`, collect them into a list.
- Sort by `EFFECT_ORDER.index(local_tag)`.
- Re-insert in sorted order.
- Unknown tags (not in `EFFECT_ORDER`) go to the end.

This addresses Pitfall 2 (effectLst child ordering) and requirement FE-03.
